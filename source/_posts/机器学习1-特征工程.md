# 特征工程的作用
特征工程的作用是把原始数据转换成更适合模型学习的特征，从而提升效果与稳定性、降低训练难度。
  - 提升预测性能：引入更有信息量的变量（如比率、差值、交叉、统计特征）。
  - 让模型更容易学到规律：把非线性/交互关系用特征显式表达（尤其线性模型）。
  - 处理数据问题：缺失值、异常值、噪声、类别编码、文本向量化、时间对齐等。
  - 提高泛化与鲁棒性：减少泄漏、稳定分布、避免线上/线下不一致。
  - 降低成本：降维、特征选择、稀疏化/压缩，减少训练和推理开销。

# 概念

## 01特征归一化
特征归一化是把特征的数值按某种规则“缩放/变换”到统一或可比较的尺度范围，让模型更容易训练、不同特征不会因量纲不同而互相干扰。
> 为什么需要归一化?

很多算法对“数值尺度”敏感，不同量纲会让训练和预测产生偏差。树模型通常不需要归一化，因为它们按阈值分裂，对单调缩放不敏感。

### 线性归一化 Min-Max Scaling
`x' = (x - min) / (max - min)（映射到 [0,1]）`
### 零均值归一化 Z-Score Normalization
也叫标准化，是把一个数值特征按其均值和标准差进行缩放，使其在训练数据上变成“均值为0、标准差为1”的量纲。

`x' = (x - μ) / σ（均值 0、标准差 1）`

      - μ：该特征在训练集上的均值
      - σ：该特征在训练集上的标准差，标准差是衡量一组数据“离平均值有多分散”的指标；*越大表示波动越大，越小表示更集中*。

`μ`和`σ`必须用训练集计算并保存，推理预测时用同一组μ和`σ`

> 如何理解“均值为0、标准差为1”?

- *均值为0*: 表示这一列数据“整体中心”被平移到0。正值代表高于原均值，负值代表低于原均值。
- *标准差为1*: 表示“离中心的典型波动尺寸”被缩放成1个单位。此时数值的大小可以理解为“离均值有多少个标准差”(也叫z值)
	-  z=1：比均值高1个标准差
	- z=2:   比均值高2个标准差



## 02 类别型特征 categorical feature
取值是表示“类别/标签”的特征，本身没有连续数值的含义。原始输入通常是字符串形式，大部分模型都必须处理转换成数值型特征才能工作。例如: 性别（male/female）、城市（北京/上海/深圳）、颜色（red/green/blue）、舱位等级（Pclass=1/2/3）、是否有房（yes/no）。


### 序号编码 Ordinal Encoding
序号编码(也叫标签编码、整数编码)是把类别型特征的每个取值用一个整数编号表示。
例如: `Embarked ∈ {S,C,Q}`可以编码为`S->0,C->1,Q->2`,那么一行数据中里`Embarked=Q`就变成数值`2`。

关键点:
- 数字只表示编号，不代表大小关系。
- 适合树模型(决策树/随机森林/GBDT);线网回归/逻辑回归/距离模型通常更推荐 one-hot。
- 训练时的映射要保存，预测时用同一份。

### 独热编码 One-hot Encoding
独热编码是把一个类别特征转换成多列0/1特征:每个可能类别一列，属于哪个类别就把那列置1，其他置0。
例如: ` Color ∈ {Red, Green, Blue}`
  - Red  → Color_Red=1, Color_Green=0, Color_Blue=0
  - Green→ Color_Red=0, Color_Green=1, Color_Blue=0
  - Blue → Color_Red=0, Color_Green=0, Color_Blue=1
如果一条数据是 `Color=Green`,独热编码后的特征向量就是[0,1,0]

### 二进制编码 Binary Encoding
二进制编码是一种把高基数类别特征压缩成较少维度的编码方式。
做法:
- 1.先把每个类别做“序号编码”，通常从1开始，0留给 unknow/缺失
- 2.再把整数 id 转换为二进制，把每一位拆成一列(0/1)
例如:
`City ∈ {Beijing, Shanghai, Shenzhen, Hangzhou, Chengdu}`
  先编号：Beijing=1, Shanghai=2, Shenzhen=3, Hangzhou=4, Chengdu=5
  5 个类别用二进制需要 ceil(log2(5+1))=3 位（假设 3 列 b2 b1 b0）：

  - Beijing (1)  → 001
  - Shanghai (2) → 010
  - Shenzhen (3) → 011
  - Hangzhou (4) → 100
  - Chengdu (5)  → 101

### 03 高维组合特征
高维组合特征是指把多个原始特征做“组合/交叉”后产生新特征。

 原始特征
  - city：北京/上海/深圳（3 类）
  - device：iOS/Android（2 类）
  - hour：0–23（数值，先分桶成 hour_bin：白天/夜晚（2 类））
  组合特征（交叉特征）
  - city × device：表示“某城市在某设备”这一组合
    可能的维度：(北京,iOS) (北京,Android) (上海,iOS) (上海,Android) (深圳,iOS) (深圳,Android) 共 3*2=6 个 one-hot 列
    如果一条样本是 city=上海, device=Android，则只有 (上海,Android)=1，其余 5 列为 0。
  - city × hour_bin：3*2=6 个组合列
    样本 深圳 + 夜晚 命中 (深圳,夜晚)=1。
  - city × device × hour_bin：三阶组合，维度变成 `3*2*2=12`。类别更多时就会迅速爆炸成“高维组合特征”。
  
  它解决什么
  - 不做组合时，你只能学到“上海整体更高/Android整体更高”；做 city×device 后，模型能学到“上海在 Android 特别高，但 iOS 一般”这种交互效应。

### 04 组合特征
组合特征(也叫交叉特征、交互特征)是把两个原始特征通过某种规则“组合”成一个新特征，用来表达它们之间的关系，而不是只看各自的独立响应。
比如泰坦尼克生存的例子: 
`FamilySize（家庭人数） = SibSp（兄弟姐妹/配偶人数） + Parch(父母/子女人数) + 1`

#### 和高维组合特征的区别
• 组合特征：泛指把多个原始特征做交叉/运算得到的新特征，维度不一定大。
  - 例：FamilySize = SibSp + Parch + 1、income_per_capita = income / family_size、city_device = city + "_" + device。

  高维组合特征：特指“交叉后产生的特征空间很大”的组合特征，常见于类别特征 one-hot 后做交叉或高基数/高阶交叉，会导致维度爆炸且很稀疏。
  - 例：city(1000类) × device(50类) → 最多 1000*50=50,000 个组合列；再加 hour_bin(24) 做三阶交叉 → 1,200,000 列。
  
  本质区别：都是“组合/交互”，但“高维组合特征”强调交叉后维度巨大（高基数、one-hot、或高阶），带来存储/计算/过拟合风险。

### 05 文本表示模型
文本表示模型(Text Representation Model)是把文本（词、句子、文档）转换成模型可处理的数值表示(向量/张量)的方法或模型，用于分类、检索、相似度、聚类、生成等任务。
常见类型(从见到到复杂):
- *离散表示* : Bags-of-Words（词袋模型）、TF-IDF、n-gram(高纬度稀疏向量)
- *分布式词向量* : Word2Vec、GloVe、FastText(低维稠密向量，词集)
- *上下文表示/句向量*: BERT/RoBERTa等Transformer输出的 token向量和句向量(随上下文变化)
- *面向索引的向量模型*: Sentence-BERT、双塔/对比学习 embedding(用于相似度检索、RAG向量库)
